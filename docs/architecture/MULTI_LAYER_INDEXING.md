# Multi-Layer Indexing Architecture

The Xanther Context Engine uses a **4-layer knowledge graph** approach to enable powerful code analysis and reasoning.

## Architecture Layers

### Layer 1: LSP (Language Server Protocol) / AST Level
**What**: Raw code structure extracted by parsers
**How**: tree-sitter parsers extract:
- Functions, methods, classes
- Variables, imports, decorators
- Call relationships
- Type annotations

**Neo4j Nodes**: `ASTNode`
**Neo4j Edges**: `CONTAINS`, `CALLS`, `IMPORTS`, `INHERITS`, `DECORATES`

**Example**:
```python
# File: auth.py
def authenticate(username, password):
    token = _validate(username, password)
    return token

def _validate(user, pwd):
    ...
```

Creates:
- `ASTNode` for `authenticate` (function)
- `ASTNode` for `_validate` (function)
- Edge: `authenticate` -[:CALLS]-> `_validate`

---

### Layer 2: Functional Components (LLD - Low-Level Design)
**What**: Function/method-level documentation
**Generated by**: `doc_generator.generate_component()`
**Contains**:
- Summary: 1-2 sentence description
- Responsibilities: What this function does
- Dependencies: What it depends on

**Neo4j Nodes**: `ComponentDescription`
**Neo4j Edges**: `DESCRIBED_BY` (ASTNode -> ComponentDescription)

**Example**:
```json
{
  "node_id": "repo:auth.py:function:authenticate",
  "summary": "Authenticates user and returns session token",
  "responsibilities": [
    "Validate credentials",
    "Generate session token",
    "Log authentication attempt"
  ],
  "dependencies": [
    "_validate",
    "token_generator",
    "logger"
  ]
}
```

---

### Layer 3: Component Documentation (LLD Detailed)
**What**: Detailed algorithm-level documentation for functions
**Generated by**: `doc_generator.generate_component_doc()`
**Contains**:
- Algorithm description: How it works internally
- Data flow: Input → Processing → Output
- Error handling: What errors can occur
- Edge cases: Special handling situations

**Neo4j Nodes**: `ComponentDoc`
**Neo4j Edges**: `DETAILED_IN` (ComponentDescription -> ComponentDoc)

**Example**:
```json
{
  "component_id": "repo:auth.py:function:authenticate",
  "algorithm_description": "Uses HMAC-SHA256 for password validation",
  "data_flow": "username, password -> hash -> compare -> token",
  "error_handling": "Raises InvalidCredentials on mismatch",
  "edge_cases": ["Empty username", "Very long password"]
}
```

---

### Layer 4: Architecture Documentation (HLD - High-Level Design)
**What**: Module/subsystem-level architecture
**Generated by**: `doc_generator.generate_architecture()`
**Contains**:
- Architectural role: What does this module do in the system
- Design patterns: Patterns used (Adapter, Factory, etc.)
- Integration points: How it connects to other modules
- Quality attributes: Non-functional properties

**Neo4j Nodes**: `ArchitectureDoc`
**Neo4j Edges**: `PART_OF_ARCHITECTURE` (ASTNode -> ArchitectureDoc)

**Example**:
```json
{
  "module_path": "auth/",
  "architectural_role": "Authentication & Authorization subsystem",
  "design_patterns": ["Strategy Pattern", "Decorator Pattern"],
  "integration_points": [
    "user_service",
    "token_manager",
    "audit_logger"
  ],
  "quality_attributes": [
    "Security: HMAC-SHA256 encryption",
    "Performance: <100ms auth time",
    "Scalability: Stateless design"
  ]
}
```

## Full Indexing Pipeline

```
┌─────────────────────────────────────────┐
│  Source Code Files                      │
│  (.py, .ts, .js, etc.)                  │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  LAYER 1: AST Parsing                   │
│  • tree-sitter parsers                  │
│  • Extract functions, classes, imports  │
│  • Build call graphs                    │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  LAYER 2: Functional Components (LLD)   │
│  • generate_component()                 │
│  • Summary + Responsibilities           │
│  • Creates ComponentDescription nodes   │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  LAYER 3: Component Docs (LLD Detailed) │
│  • generate_component_doc()             │
│  • Algorithm, Data Flow, Error Handling │
│  • Creates ComponentDoc nodes           │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  LAYER 4: Architecture (HLD)            │
│  • generate_architecture()              │
│  • Module role, patterns, integration   │
│  • Creates ArchitectureDoc nodes        │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  Embeddings Generation                  │
│  • Convert all nodes to vectors         │
│  • 1536-dimensional embeddings          │
│  • Enable semantic search                │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  Neo4j Storage & Indexing               │
│  • Store all nodes and edges            │
│  • Create vector indexes                │
│  • Build constraint indexes             │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  Graph RAG Ready for Agents             │
│  • ArchitectureAgent                    │
│  • TraceabilityAgent                    │
│  • ImpactAnalysisAgent                  │
│  • SearchDiscoveryAgent                 │
└─────────────────────────────────────────┘
```

## Neo4j Schema Overview

### Nodes

| Type | Purpose | Created By |
|------|---------|-----------|
| ASTNode | Raw code elements | Parser |
| ComponentDescription | Function-level summary | generate_component() |
| ComponentDoc | Detailed function docs | generate_component_doc() |
| ArchitectureDoc | Module-level architecture | generate_architecture() |
| Embedding | Vector embeddings | generate_embeddings() |

### Relationships

| Relationship | Direction | Purpose |
|---|---|---|
| CONTAINS | Parent -> Child | Module contains function |
| CALLS | Function -> Function | Call dependency |
| IMPORTS | Module -> Module | Import dependency |
| INHERITS | Class -> Parent | Inheritance |
| DESCRIBED_BY | ASTNode -> ComponentDescription | Links code to layer 2 |
| DETAILED_IN | ComponentDescription -> ComponentDoc | Links layer 2 to layer 3 |
| PART_OF_ARCHITECTURE | ASTNode -> ArchitectureDoc | Links code to layer 4 |
| HAS_EMBEDDING | ASTNode -> Embedding | Links to vector |

## How Agents Use the Multi-Layer Graph

### ArchitectureAgent
Uses layers: **Layer 1** (ASTNode) + **Layer 4** (ArchitectureDoc)
```
Query: "Show architecture of auth module"
→ Find auth module nodes (Layer 1)
→ Get ArchitectureDoc via PART_OF_ARCHITECTURE (Layer 4)
→ Return patterns, integration points, role
```

### TraceabilityAgent  
Uses layers: **Layer 1** → **Layer 2** → **Layer 3** → **Layer 4**
```
Query: "Trace authenticate() to architecture"
→ Find authenticate() ASTNode (Layer 1)
→ Get ComponentDescription via DESCRIBED_BY (Layer 2)
→ Get ComponentDoc via DETAILED_IN (Layer 3)
→ Get ArchitectureDoc via PART_OF_ARCHITECTURE (Layer 4)
→ Return full chain with explanations
```

### ImpactAnalysisAgent
Uses layers: **Layer 1** (for CALLS/IMPORTS relationships)
```
Query: "What breaks if I change authenticate()?"
→ Find authenticate() ASTNode (Layer 1)
→ Reverse CALLS/IMPORTS edges (Layer 1)
→ Get callers and their risks
→ Check if test files reference it
```

### SearchDiscoveryAgent
Uses layers: **Layer 1** (structure) + **All layers** (embeddings)
```
Query: "How do we handle authentication?"
→ Semantic search across all embeddings
→ Find matching ASTNodes (Layer 1)
→ Enrich with ComponentDescription (Layer 2)
→ Return with algorithm details (Layer 3)
```

## Example: Complete Multi-Layer Trace

**User Query**: "How does login work in the auth module?"

**Agent Flow**:
```
1. SearchAgent finds "login" function
   → Layer 1: ASTNode for login()
   
2. ArchitectureAgent provides context
   → Layer 4: auth module is "Authentication subsystem"
   → Patterns: "Decorator for request validation"
   
3. TraceabilityAgent traces the chain
   → Layer 1: login() calls _validate()
   → Layer 2: login "Validates user and creates session"
   → Layer 3: _validate uses "HMAC-SHA256 password validation"
   → Layer 4: Part of "Security & Authorization" architecture
   
4. ImpactAnalysisAgent shows dependencies
   → Layer 1: login() is called by 3 endpoints
   → Tests that exercise it: test_auth.py (2 tests)
   → Risk: High (many callers)

5. Final Response combines all layers:
   
   "The login() function in the auth module:
   
   **Role** (Layer 4): Core authentication component
   - Part of the Authentication & Authorization subsystem
   - Uses Decorator Pattern for request validation
   
   **Function** (Layer 2): 
   - Validates user credentials
   - Creates and returns session token
   
   **Algorithm** (Layer 3):
   - Uses HMAC-SHA256 for password hashing
   - Flow: username → validate → token → return
   - Error: Raises InvalidCredentials on mismatch
   
   **Impact** (Layer 1):
   - Called by 3 endpoints
   - Tested by 2 test cases
   - High risk if changed (many dependencies)
   
   **Recommendation**: Use UpdateData patch, add tests"
```

## Benefits of Multi-Layer Approach

1. **Context at Multiple Levels**: From raw code to architectural decisions
2. **Semantic Understanding**: Each layer adds meaning
3. **Agent Intelligence**: Agents can reason across layers
4. **IDE Integration**: Better context for developers
5. **Code Review**: Understand implications of changes
6. **Documentation**: Auto-generated at all levels
7. **Search**: Find by function, by architecture, by pattern
